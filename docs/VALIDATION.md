## Physical Android acceptance — required before presenting live GPS

1. Deploy the backend to HTTPS, build and install the standalone preview APK, and set its server URL.
2. In ChatGPT Plugins, use Add → Add custom MCP server with the hosted `/mcp` URL and no authentication, review and create/install the personal plugin, then invoke `start_pairing` and confirm the card shows a new eight-character code. Current official setup: https://developers.openai.com/apps-sdk/deploy/connect-chatgpt .
3. Pair the phone. Confirm the code cannot be reused on a second device and that pairing alone does not upload GPS.
4. Start sharing and grant foreground/background location and notification permissions. Check the persistent foreground-service notification.
5. Switch to ChatGPT, request status, and record its update time and accuracy. Wait for a later update while the companion is backgrounded. Repeat with the phone locked.
6. Request nearby restaurants. Confirm the server makes one requested lookup, returns at most five candidates, and does not claim GPS identifies the restaurant with certainty.
7. Choose a restaurant, load its official menu, check source links, apply dietary preferences, and ask about one dish.
8. Repeat the menu request and confirm the 24-hour cache avoids duplicate retrieval charges.
9. Turn off network access, stop sharing, and verify local collection stops immediately. Restore connectivity and reopen the companion; confirm server deletion completes.
10. Deny each permission in turn. Confirm clear guidance and no false “sharing” state. Re-enable permissions in Android settings and restart explicitly.
11. Test poor GPS accuracy indoors, an old fix, and a missing menu. The app should ask for a refresh/search or menu URL/text, with no fabricated dishes or nutrient numbers.
12. Force-stop the app. Updates should stop; the server must mark the last fix stale after five minutes and clear it after fifteen. Reopen and restart sharing explicitly.
13. Check two-hour expiry. Server rejects later writes, and the companion stops on its next callback or foreground refresh.

## Honest failure behavior

- Background delivery remains subject to Android power management and force-stop rules.
- No continuous location history is maintained by the application; ordinary database backups/WAL can retain older record versions according to your infrastructure retention policy.
- “Needs confirmation” is not proof a dish is safe for an allergy. General cooking context is distinct from restaurant-confirmed ingredients.
- No paid provider calls are part of automated tests. Signed timeouts retain their budget reservation for manual reconciliation.
